════════════════════════════════════════════════════════════════════════
  SUMMARY — What is stored where when store=True
════════════════════════════════════════════════════════════════════════
  Layer           |  What is stored                            |  Retention / control    
  ───────────────────────────────────────────────────────────────────────────────────────
  Microsoft/Foundry   |  Full request (system prompt + user msg)   |  Stored until deleted;  
     (Responses   |  Full completion (model output)            |    delete via API, or   
      API store)  |  Response ID for retrieval & chaining      |    per Microsoft retention  
  Fireworks       |  KV-cache of prompt prefix (RAM only)      |  Minutes–hours, evicted 
     (cache)      |    — prompt caching, independent of store  |    oldest-first; never  
                  |                                            |    persisted to disk    
  Fireworks logs  |  Metadata only (token counts)              |  Operational, no content

  Recommendation for MELI's classifier workload:
  ─────────────────────────────────────────────────────────────────────
  • store=False (default in the other demos) is the right choice for a
    stateless classifier — nothing persists, best data-retention posture.
  • store=True is useful when you NEED statefulness: audit trails,
    conversation chaining (previous_response_id), or deferred retrieval
    of classification decisions.
  • Either way, prompt caching (prompt_cache_key) works independently
    and only ever touches volatile memory on the Fireworks replicas.
